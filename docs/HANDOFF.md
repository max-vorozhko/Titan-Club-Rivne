## 6. Firebase

- Проєкт: **titan-run** (`js/config.js`). Ключі публічні за задумом Firebase; захист — правила.
- Authentication: увімкнено **Anonymous**; дозволений домен `max-vorozhko.github.io` додано.
- Firestore (регіон eur3):
  - `scores/{uid}` — «Біг»: `{name, km, coins, time, updatedAt}`, лише покращення км.
  - `sunday/{понеділок YYYY-MM-DD}/{5k|10k}/{uid}` — «Неділя»: `{name, time, stumbles, updatedAt}`; писати лише в поточний тиждень, лише покращення часу, ≥200 с/км.
  - `draw/{titan|heart|star|rivne}/runs/{uid}` — «Малюнок»: `{name, points, t, key, dayStart, updatedAt}`, лише покращення `key`.
  - `trail/{7k|13k|26k}/runs/{uid}` — «Трейл»: те саме поле, ≥150 с/км, ≤3600 с/км.
  - Скрізь: лише власний документ, без видалення, `updatedAt == request.time`, ім'я 2–20 символів.
- **Правила публікує власник вручну:** Firebase Console → Firestore Database → Rules → вставити ВЕСЬ `firestore.rules` → Publish. На телефоні редактор може бути під історією версій — простіше з комп'ютера або «версія для ПК». Пряме посилання: https://console.firebase.google.com/project/titan-run/firestore/rules
- Видалити фейковий результат: Firestore → Data → відповідний документ → Delete.
- Перевірка, що правила живі (без запису), — GET через REST:
  `https://firestore.googleapis.com/v1/projects/titan-run/databases/(default)/documents/<шлях>?pageSize=1&key=<apiKey>` — 200 = читання дозволене, 403 = правило відсутнє.

## 8. Як перевіряли (відтворити в новій сесії)

- Локальний сервер: `python3 -m http.server 8765` у корені репо.
- Браузер: Playwright + Chromium (у середовищі Claude вже встановлені), в'юпорт телефона 390×760; `window.TITAN_CONFIG = { firebase: null }` через `addInitScript`, щоб не писати в прод.

- Firebase локально: `npm i firebase-tools@14 @firebase/rules-unit-testing@4 firebase@11` (у scratchpad), `firebase emulators:start --only auth,firestore --project demo-titan`; конфіг гри `{ firebase: {apiKey:'demo-key', projectId:'demo-titan', authDomain:'x'}, emulator: true }`; запити до jsDelivr підміняли локальними файлами SDK через `context.route`.
- Тести правил: `@firebase/rules-unit-testing` — 52 сценарії (scores 16, sunday 18, trail 18), усі проходили.
- Мережа середовища Claude не пускає на github.io, Google Maps і Google Drive-лінки напряму; Firestore/Identity Toolkit REST — доступні.

## 7а. Профіль, мерч і бусти

**Статус: працює на сайті.** Правила з профілями/кодами й адміном опубліковані (перевірено REST-запитами),
власник сам вставив посилання на банку в `donateUrl`, тест промокоду пройшов («ніби зробив»).

- **Ідентифікація лише за пристроєм** (анонімний Firebase uid + localStorage). Вхід через email/Google власник свідомо відклав — «може відлякати».
- Вигляд аватара, статистика, серія днів і відкриті досягнення — у localStorage (`titan.profile.v1`).
- Досягнення → мерч (список `ACHIEVEMENTS` у `js/profile.js`, речі — `OPTIONS` у `js/avatar.js`): серія 3/7 днів, Біг 10/42,2 км, фініш Неділі, трейл/26 км, топ-3 тижня, перше місце.
- **Буст «Супер-кросівки»:** один забіг у «Неділі»/«Трейлі», швидкість ×1.01 (≈ −3,5 с/км), золоті кросівки; результат з полем `boost: true` → «⚡» у таблицях. Ціна — донат 30 грн на банку Monobank (`boostPrice`, `donateUrl`, `promoContact` у `js/config.js`), після оплати власник вручну надсилає одноразовий промокод.
- Firestore: `profiles/{uid}` `{boosts, lastCode, updatedAt}` (+1 лише разом із погашенням коду в тій самій транзакції, −1 на старті забігу); `codes/{КОД}` `{used, createdAt, usedBy, usedAt}` — створює/бачить лише адмін.
- **Адмін:** промокоди генерує лише власник (`isOwner()` у `firestore.rules`): вхід через Google з роллю `owner` у колекції `admins` (див. розділ 7б). Старий анонімний uid пристрою `L5F6ELplpsaOGeqSiOqiyoYPTBl1` поки лишено в `isOwner()` як запасний; коли вхід через Google запрацює — можна прибрати. Коди формату `TR-XXXX-XXXX`.
- **Ручна видача (поточний процес):** гравець донатить 30 грн на банку з ім'ям із гри в коментарі → пише @max_vorozhko → власник на `admin.html` генерує/копіює код `TR-XXXX-XXXX` → гравець вводить у «Профілі» → «Активувати».
- В таблицю потрапляє лише **кращий** час гравця; якщо забіг із бустом повільніший за попередній, у таблиці ⚡ не з'явиться (бусти списуються все одно).
- **Автоматизацію обговорили, але власник вирішив поки лишити ручний варіант.** План на потім:
  - *Варіант 1 (рекомендований):* у профілі «Купити» → код замовлення гравця (напр. `TR-7K3P`) → донат на банку з цим кодом у коментарі → особистий API Monobank (webhook) → Firebase Cloud Function перевіряє суму ≥ `boostPrice` і нараховує буст на uid; нерозпізнані платежі — в адмінку для ручного нарахування. Потрібно: тариф Blaze (+ бюджетне сповіщення), особистий токен Monobank у секретах (НЕ в чат/код), автопублікація Functions через GitHub Actions із сервісним акаунтом.
  - *Варіант 2:* WayForPay / LiqPay / Plata by mono з checkout і webhook — потрібні ФОП, договір, оферта й умови повернення.

## 7б. Адмінка клубу й відвідуваність неділь

- **Головні дані — в адмінці**, Google-таблиця «Titan Club Rivne 2026» лише копія (кнопка «Вивантажити»). Імпорт з таблиці — один раз, для історії.
- **Вхід:** `admin.html`, кнопка «Увійти через Google». Окремий екземпляр Firebase (`club-admin`), тож анонімний гравець гри в тому ж браузері не змінюється.
- **Ролі:** колекція `admins/{email}` з полем `role`: `owner` (власник: усе + промокоди) або `admin` (відвідуваність, атлети, таблиця). Створюється вручну у Firebase Console; з сайту її змінити не можна, а email-и не потрапляють у публічний репозиторій.
- **Firestore:**
  - `athletes/{id}` — `{name, persona, emoji, active, updatedAt}`: реальні імена, лише адміни.
  - `runs/{рік-тиждень}` (напр. `2026-45`) — `{date, km, present: [id атлетів], updatedBy: email, updatedAt}`: лише адміни.
  - `club/public` — `{athletes: {id: {p: персонаж, e: емодзі, a: активний}}, runs: {id: {date, km, present}}, updatedAt}`: читають усі (вкладка «Клуб»), пишуть адміни. **Реальних імен тут немає.**
- **Тижні:** номер як у таблиці й у «Неділі» (ISO, з понеділка): тиждень 44 = неділя 1 листопада 2026.
- **Кілометри:** одна дистанція на пробіжку; «Км клубу» = сума (км × кількість учасників). Імпортовані з таблиці неділі без км — адмін дописує.
- **Google-таблиця:** доступ просимо лише при імпорті/вивантаженні (scope `spreadsheets`, токен ~1 год у пам'яті). Вивантаження перезаписує `Аркуш1` (A1:BE300) у тому самому форматі й аркуш «Кілометри». Налаштування — `attendanceSheet` у `js/config.js`.
- **Налаштування власником (один раз):** Firebase → Authentication → увімкнути Google; Authorized domains — `max-vorozhko.github.io`; Firestore → колекція `admins` з двома документами; Google Cloud (проєкт titan-run) → увімкнути Google Sheets API, OAuth consent screen у режимі Testing з обома email у Test users; таблицю відкрити другому адміну на редагування.
- **Тести:** правила — 33 сценарії (`admins`, `athletes`, `runs`, `club/public`, `codes` за ролями); адмінка — Playwright на емуляторах (вхід через `signInWithCredential` з тестовим Google-токеном, Google Sheets API підмінений).

## 7в. Позначки ▲/▼/NEW у таблицях

- **Біг, Неділя, Трейл:** зміна місця відносно початку доби за київським часом, однакова для всіх. Кожен запис має необов'язкове поле `dayStart` — свій результат на початок доби, коли його востаннє змінювали (`null` — запис з'явився того дня). «Вчорашнє» місце рахується з цих значень; записи без `dayStart` (старі версії гри) — без позначки.
- **NEW:** лише новий гравець у таблиці (`dayStart == null`). У Неділі — лише якщо гравця не було й у таблиці минулого тижня.
- Таблиці тепер читаються цілком (колекції невеликі), місце рахується як «кількість кращих + 1».
- **Клуб:** «Найвірніші» й «Усі учасники» — відносно попередньої неділі (місце за кількістю пробіжок до і після останньої неділі); NEW — перша пробіжка була на останній неділі.
- **Правила:** `dayStartOk()` — у нового запису `null`, далі попередній результат або попередній `dayStart`. Тести — 9 сценаріїв.

## 7г. Додаток на екрані телефона (PWA)

- `manifest.webmanifest` (назва «Titan Run», іконки в `assets/icons/`, повний екран), теги `apple-*` в `index.html`.
- `sw.js`: сторінка — спершу з мережі (оновлення приходять одразу), без мережі — з кешу; файли з `?v=N` — з кешу. Firebase, Google, статистика й адмінка йдуть повз кеш. **При релізі збільшуйте `CACHE` у `sw.js` разом із `?v=N`.**
- `js/pwa.js`: підказка на головній «Додай Titan Run на екран» — на iPhone інструкція для Safari (у Telegram — «відкрий у Safari»), на Android кнопка «Встановити»; закрити — ховається на 14 днів; у встановленому додатку не показується. Події GoatCounter: `pwa-open`, `pwa-install`.
- **Адмінка як окремий додаток:** `admin.webmanifest` (id/scope `admin.html`, «Titan Адмін»), іконки `assets/icons/admin-*` зі смугою «АДМІН». У встановленій адмінці (standalone) вхід — переходом на сторінку Google (`response_type=id_token`, перевірка `nonce`) з поверненням на `admin.html`, бо вікна входу в iOS-додатку часто не повертають результат. Для цього в OAuth-клієнті в **Authorized redirect URIs** має бути `https://max-vorozhko.github.io/Titan-Club-Rivne/admin.html`. Доступ до Google-таблиці у встановленій адмінці на iPhone може не відкритися — тоді з Safari чи комп'ютера.
- Справжній iOS/Android-додаток (Flutter): обговорено — на iPhone без акаунта Apple ($99/рік) роздавати файлом не можна; для Android можливий `.apk`. Поки зупинились на PWA.

## 7д. Режим «Малюнок дня»

- Світ 800×1000 умовних одиниць, полотно лише масштабує. Малюнки — набір штрихів (`GLYPHS`, `heart()`, `star()`), пунктир семплюється точками через 7 одиниць; точка «покрита», коли бігун пройшов ближче за `RC`; «дорога» — `R`.
- Бали: `700·покриття + 200·(1−зайвий слід) + 100·min(1, пар/час)`; «зайвий слід» — довжина поза контуром понад допуск на переходи між штрихами. Фініш автоматично при покритті ≥ 95%, або кнопкою «Фініш» (від 60%).
- Малюнок дня: `dayNumber(київська дата) % кількість малюнків`; серія — дні з виконаним малюнком дня (≥ 500 балів), `localStorage` ключ `titan.draw.v1`. Профіль: `Profile.record({mode:"draw"})` рахує лише забіг і серію днів (без км).
- Пауза при виході з вкладки чи згортанні. Аналітика: `run-draw-<id>`.
- **Рейтинг:** `draw/{titan|heart|star|rivne}/runs/{uid}` — `{name, points, t (десяті секунди), key = points·10000 − t, dayStart, updatedAt}`; лише покращення `key`, ▲▼/NEW через `dayStart` (як в інших таблицях). Правила `validDraw`: бали ≤ 1000, `t ≥ 1 с`, та мінімальний час за довжиною контуру (`drawLen(id)` — довжини з `js/draw.js`, **при зміні малюнків оновлювати разом**). Таблиця — розділ «Малюнок» у вкладці «Рейтинг» (`window.openLeaders(mode, id)` з `js/app.js`), ім'я просять після першого результату.
- **Не зроблено (ідеї):** щоденна таблиця «Малюнок дня» з 👑, ачівка «Художник» з мерчем, нові малюнки, малювання реальним маршрутом (GPX).
- Прототип у Claude (приватний): https://claude.ai/artifact/35AgwAz14kRKSbJgsaUxvn

## 9. Ключові константи балансу

- **Біг** (`js/game.js`): старт 340 px/с, макс 780, 4000 px = 1 км; енергія −(2.6 + 0.08·км)/с, вода +30.
- **Неділя** (`js/sunday.js`): група 420 px/с, 1 км = 36 с гри, `TIME_SCALE` 10 (темп групи 6:00/км); «Темп» ×1.4 за −4.5 енергії/с; поруч з групою (<260 px) +1.6/с; спіткнутися = ×0.45 на 0.9 с. Бот: 5 км ≈ 28–30 хв.
- **Трейл** (`js/trail.js`): 1 км по рівному = 15 с гри, `TIME_SCALE` 24; підйом ×1/(1+5·ухил), спуск до ×1.3; витрата 0.4 + 18·ухил (+60% під «Темпом») + 4 за «Темп»; без сил ×0.6. D+ 275/579/1099 м. Бот: 7 км ≈ 41–48 хв, 26 км ≈ 3:00–3:46.
- Пороги в правилах (`firestore.rules`) мають лишатися нижче за найшвидший можливий час у грі — при зміні балансу перерахувати.
